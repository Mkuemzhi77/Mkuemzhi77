# Оценка учебных проектов (опыт + знания)

Критерии: интерес / вовлечённость, польза для резюме и собесов, инженерная глубина, сложность для двоих, риск «завязнуть», демо-эффект.

Шкала оценок: **1–10**.

**Короткий вердикт:**

- Лучший баланс хардкора и вайба → **#4**, если готовы к геймблинг-серой зоне в портфолио; иначе **#1**

## 1) Игровой маркетплейс / P2P-площадка цифровых товаров

**Аналоги:** Steam Community Market, Buff, CS.Money (упрощённо)

### Характеристики

| Параметр | Оценка / описание |
|----------|-------------------|
| Интерес | 8/10 — игровая тема цепляет, но UI ордеров скучнее кейсов |
| Польза для опыта | **10/10** — транзакции, consistency, order book = топ для собесов |
| Инженерная глубина | **10/10** — race conditions, изоляции, escrow, идемпотентность |
| Frontend-нагрузка | Средняя (каталог, ордера, инвентарь) |
| Backend-нагрузка | Очень высокая (ядро — trading engine) |
| Срок MVP (двое) | 6–10 недель до «честного» матчинга + escrow |
| Стек (логично) | Go/Python + PostgreSQL + Redis + JWT; фронт React/Next |
| Тесты / CI | Обязательны — без них проект ломается на гонках |
| Портфолио / HR | Отлично: «делал order matching и escrow» звучит сильно |

### Что прокачаете

- Транзакции БД, уровни изоляции, `SELECT FOR UPDATE`, optimistic locking
- Order book / matching engine
- Escrow и состояние сделки (state machine)
- Идемпотентность платежей, двойное списание
- Индексы, миграции, интеграционные тесты, CI/CD

### Плюсы

- Максимальная ценность для backend-собесов
- Чёткая архитектура по сервисам/модулям
- Легко объяснить сложность на интервью («как не продать один скин дважды»)

### Минусы / риски

- Скучнее демо, чем кейсы/квизы
- Легко утонуть в «идеальном» order book и не дойти до UI
- Юридически аккаунты/ключи — серая зона; для учебного проекта лучше **скины/виртуальные предметы внутри своей БД**, без реальных Steam API сделок

### MVP-скоуп (чтобы не умереть)

1. Регистрация, баланс (виртуальные деньги), инвентарь
2. Sell/Buy orders по одному типу предмета
3. Атомарный match + перевод предмета и денег
4. История сделок + простые тесты на гонку (два покупателя → один победитель)

### Кому брать

Если цель — **серьёзный backend-опыт и сильная строка в резюме**. Скучновато визуально, но это «золото» для знаний.

## 2) SaaS бронирование и ресурсы (YPlaces / CRM услуг)

**Аналоги:** YCLIENTS, Dikidi, Calendly (B2B-часть)

### Характеристики

| Параметр | Оценка / описание |
|----------|-------------------|
| Интерес | 6/10 — полезно, но вайб «офисный продукт» |
| Польза для опыта | **9/10** — мультитенантность, доменная логика, интеграции |
| Инженерная глубина | 8/10 — слоты, пересечения, race на бронь |
| Frontend-нагрузка | Высокая (календарь, админка тенанта) |
| Backend-нагрузка | Высокая (правила слотов, изоляция тенантов) |
| Срок MVP (двое) | 5–8 недель до брони + календарь + 1 тенант |
| Стек (логично) | Nest/Django/FastAPI + PostgreSQL; фронт React + календарь |
| Тесты / CI | Важны на пересечениях слотов |
| Портфолио / HR | Отлично для продуктовых/fullstack вакансий, «близько к работе» |

### Что прокачаете

- Multi-tenancy (изоляция данных компаний)
- Генерация свободных окон, исключения (перерывы, праздники)
- Race condition на одном слоте
- Фоновые воркеры и уведомления (Telegram/WhatsApp)
- RBAC: владелец / мастер / клиент

### Плюсы

- Самый «взрослый» продукт — похож на реальную работу
- Можно реально использовать (барбершоп друга и т.п.)
- Хорошо делится на модули между двумя людьми (админка vs booking engine)

### Минусы / риски

- Меньше «вау» для друзей и соцсетей
- Календарный UI — боль и время
- Легко расползтись в CRM «на всё»: филиалы, зарплаты, склад…

### MVP-скоуп

1. Один тенант, мастера, услуги, график
2. Клиент выбирает слот → бронь с защитой от double-book
3. Список записей + напоминание (хотя бы email/Telegram бот)
4. Базовая админка владельца

### Кому брать

Если хотите **проект «как на работе»** и не гонитесь за игровым вайбом. Сильный fullstack/product опыт, чуть меньше «хайпа», чем у 1 и 4.

## 3) Real-time квизы / викторины (Kahoot / Quizizz)

**Аналоги:** Kahoot, Quizizz, Jackbox (частично)

### Характеристики

| Параметр | Оценка / описание |
|----------|-------------------|
| Интерес | **9/10** — весело делать и тестировать с друзьями |
| Польза для опыта | 7/10 — сильный realtime/WebSocket, слабее «финтех-логика» |
| Инженерная глубина | 7/10 — fan-out, синхронизация комнаты, scoring |
| Frontend-нагрузка | **Очень высокая** (ведущий-экран + мобильный клиент + анимации) |
| Backend-нагрузка | Средняя–высокая (комнаты, сокеты, подсчёт очков) |
| Срок MVP (двое) | **3–6 недель** до играбельной комнаты |
| Стек (логично) | Node/Go + WebSocket (Socket.IO / ws) + Redis; фронт React |
| Тесты / CI | Полезны, но демо важнее юнит-тестов на старте |
| Портфолио / HR | Хорошо для fullstack/frontend + «делал realtime на N клиентов» |

### Что прокачаете

- WebSocket-архитектура, комнаты, reconnect
- Синхронизация состояния (вопрос, таймер, лидерборд)
- Scoring с учётом скорости
- Админка сценариев квизов + медиа
- UX под нагрузку «все жмут одновременно»

### Плюсы

- Быстрее всех доходит до «можно показать друзьям»
- Идеально для парной работы: один — host UI + анимации, второй — socket server
- Низкий риск юридички / серых тем

### Минусы / риски

- Меньше уникальности на собесе, чем order book / escrow
- Легко сделать «красивую игрушку» без серьёзной архитектуры
- Масштаб «сотни игроков» нужно эмулировать; иначе останется toy-проект

### MVP-скоуп

1. Создание квиза (вопросы, таймер, баллы)
2. Комната по коду, join с телефона
3. Синхронный раунд + лидерборд
4. Экран ведущего на TV/проектор

### Кому брать

Если важны **скорость результата, веселье и realtime**. Для «прокачки мозга на транзакциях» слабее #1 и #4.

## 4) Кейсы в реальном времени + инвентарь + виртуальная валюта

**Аналоги:** кейс-сайты / skin gambling (учебный клон экономики)

### Характеристики

| Параметр | Оценка / описание |
|----------|-------------------|
| Интерес | **10/10** — максимальный вайб и вовлечённость |
| Польза для опыта | 8/10 — экономика, RNG, инвентарь, realtime; чуть меньше «биржи», чем #1 |
| Инженерная глубина | 9/10 — атомарность открытия, баланс, антиабуз |
| Frontend-нагрузка | Высокая (анимации открытия, инвентарь, live-лента) |
| Backend-нагрузка | Высокая (экономика, fair RNG, консистентность) |
| Срок MVP (двое) | 5–8 недель до кейсов + инвентарь + live drop feed |
| Стек (логично) | Go/Node + PostgreSQL + Redis + WebSocket; фронт с тяжёлой анимацией |
| Тесты / CI | Критичны на балансе и «нельзя получить предмет без списания» |
| Портфолио / HR | Технически сильный; **осторожно с формулировками** (gambling association) |

### Что прокачаете

- Виртуальная экономика: баланс, инвентарь, история операций
- Provably fair / честный RNG + веса дропа
- Атомарное «списали валюту → выдали предмет»
- Realtime: лента дропов, онлайн-открытия
- Антиабуз: rate limits, идемпотентность открытия кейса

### Плюсы

- Топ по мотивации делать каждый день
- Красивое демо, вирусность среди знакомых
- Много пересечений с #1 (инвентарь, баланс), но «слаще» UX

### Минусы / риски

- Ассоциация с гемблингом — в резюме лучше писать как **«virtual item economy / lootbox simulator (educational)»**
- Легко увлечься анимациями и забить на целостность данных
- Монетизация/реальные деньги — не трогать в учебном проекте

### MVP-скоуп

1. Регистрация, виртуальный баланс (без донатов деньгами)
2. 2–3 кейса с таблицей дропа
3. Открытие с анимацией + запись в инвентарь
4. Live-лента последних дропов по WebSocket
5. (Опционально) контракты/апгрейд — только после стабильного ядра

### Кому брать

Если хотите **максимум драйва** и готовы дисциплинированно делать экономику, а не только «крутилку». По пользе близко к #1, по кайфу выше.

## Как выбрать (дерево решений)

1. **Нужен максимум пользы на backend-собесы** → берите **#1**
2. **Нужен кайф + красивое демо, но всё ещё хардкор** → берите **#4**
3. **Хотите быстро играть с друзьями и прокачать сокеты** → берите **#3**
4. **Хотите «как настоящий SaaS на работе»** → берите **#2**
5. **Не можете выбрать между хардкором и вайбом** → **#4 как основной**, а матчинг ордеров из #1 добавить позже как «маркет предметов из инвентаря» (гибрид 4→1)

### Гибрид (если амбиции большие)

Оптимальный учебный путь на семестр:

1. Старт: **#4** (баланс, инвентарь, кейсы, live) — мотивация
2. Развитие: P2P-торговля предметами из инвентаря (**кусок #1**) — order/escrow
3. Не начинать #2 и #3 параллельно — распыление убьёт оба проекта

## Рекомендация для пары (опыт + знания)

| Приоритет | Тема | Почему |
|-----------|------|--------|
| **1-й выбор** | **#4 Кейсы + экономика** | Лучший баланс интереса и жёсткой логики; дольше не забросите |
| **2-й выбор** | **#1 Маркетплейс** | Если оба горите backend и готовы к «сухой» биржевой логике |
| **3-й выбор** | **#3 Квизы** | Если хотите быстрый видимый результат и realtime |
| **4-й выбор** | **#2 SaaS** | Если цель — портфолио под продуктовую/enterprise разработку |

**Практичный совет по разделению ролей:**
- Один человек: core backend (транзакции, экономика/матчинг, тесты)
- Второй: frontend + realtime UX + админка
- Общее: схема БД и API-контракт в первую неделю

**Красные флаги (любая тема):**
- Нет жёсткого MVP на 2–3 недели → проект раздуется
- Реальные платежи / чужие аккаунты / гемблинг на деньги — не надо для учёбы
- «Микросервисы с нуля на 8 сервисов» — оверкилл; начните с модульного монолита

## Альтернативные проекты (советы сверх ваших 4 тем)

Критерии те же: интересно делать вдвоём + реально прокачивает навыки, а не «ещё один CRUD-блог».

### Топ-рекомендации

| # | Проект | Интерес | Опыт | Почему стоит |
|---|--------|---------|------|--------------|
| A | **Мини-банк / кошелёк** (переводы, холды, выписки) | 7 | **10** | Чистая транзакционная логика без гемблинг-вайба; идеально для собесов |
| B | **Тикетная система / Eventbrite-lite** (события, места, QR) | 8 | 9 | Race на места + платения + красивое демо |
| C | **Realtime-чат / Discord-lite** (комнаты, presence, вложения) | **9** | 8 | Сокеты, fan-out, поиск, права — сильный fullstack |
| D | **Коллаб-доска / Miro-lite** (фигуры, курсоры, комнаты) | **9** | 8 | CRDT/операции, WebSocket, крутое визуальное демо |
| E | **Уведомления как сервис** (email/Telegram/push, очереди, ретраи) | 5 | **9** | То, что реально есть на работе; воркеры, идемпотентность |
| F | **Файловое хранилище** (upload, signed URL, шаринг) | 6 | 8 | S3-паттерны, ACL, превью — сильный infra/backend |
| G | **Мультиплеер-игра с матчмейкингом** (шахматы / 2D-арена) | **10** | 7 | Кайф максимум; меньше «взрослого» домена, больше стейт-машины |
| H | **Прайс-агрегатор + алерты** (парсинг/API, подписки) | 7 | 7 | Джобы, дедуп, уведомления; легче войти, чуть слабее уникальность |

### Короткие карточки

#### A) Мини-банк / внутренний кошелёк
- **Сок:** перевод A→B атомарно, hold/capture, идемпотентные операции, ledger (двойная запись).
- **MVP:** счета, перевод, история, защита от double-spend.
- **Кому:** хотите хардкор #1/#4, но без кейсов и скинов в резюме.

#### B) Билеты на события (Eventbrite / Яндекс Афиша lite)
- **Сок:** ограниченный inventory мест, параллельная покупка, QR на входе, отмена/возврат статуса.
- **MVP:** создание ивента → выбор места → бронь → QR.
- **Кому:** если #2 скучновато, а race conditions всё равно хочется — это веселее брони к мастеру.

#### C) Discord / Slack lite
- **Сок:** каналы, DM, online/offline, typing, роли, поиск по истории.
- **MVP:** сервер → каналы → realtime-сообщения → presence.
- **Кому:** любите фронт+сокеты; быстрее «оживает», чем биржа.

#### D) Совместная доска (Miro / Excalidraw lite)
- **Сок:** синхронизация объектов, конфликтные правки, чужие курсоры.
- **MVP:** комната по ссылке → фигуры/стикеры → realtime для 5–10 человек.
- **Кому:** сильный wow-эффект на защите/в портфолио.

#### E) Notification platform
- **Сок:** шаблоны, каналы доставки, retry/DLQ, rate limits, статус доставки.
- **MVP:** API «отправь» → очередь → Telegram/email → лог статусов.
- **Кому:** максимально «как на работе»; вайб ниже, польза высокая. Хорошо как **модуль** к #2/#3/#4, а не как единственный проект.

#### F) Свой «мини-S3» / файловый диск
- **Сок:** multipart upload, signed links, публичные/приватные объекты, шаринг по TTL.
- **MVP:** upload/download, папки, ссылка «на 24 часа».
- **Кому:** тянет в сторону backend/infra.

#### G) Мультиплеер + матчмейкинг
- **Сок:** лобби, рейтинг, reconnect, античит на уровне правил, авторитетный сервер.
- **MVP:** очередь → комната → партия до конца → рейтинг.
- **Кому:** максимальная мотивация; на собесе объяснять сложнее, чем ledger/order book.

#### H) Трекер цен / алерты
- **Сок:** периодические джобы, нормализация данных, подписки, дедуп алертов.
- **MVP:** 1–2 источника → график цены → Telegram «цена упала ниже X».
- **Кому:** быстрый старт; можно вырастить, но потолок ниже A–D.

| Хотим красивое realtime-демо | **C Чат** или **D Доска** (или ваш **#3**) |
| Хотим максимально похоже на работу | **#2 SaaS** + модуль **E Уведомления** |
| Боимся забросить через месяц | Не берите E/F как основной — скучновато без продукта вокруг |

### Антирекомендации (часто берут и жалеют)

- Ещё один Todo / блог / «магазин футболок» без сложной логики
- Клон Instagram целиком (лента + сторис + reels + DM) — слишком широко
- «Микросервисы на Kubernetes с нуля» без продукта
- Крипто/биржи с реальными ключами и деньгами
- LLM-обёртка без своей доменной логики (слабо на собесе, если нет пайплайна/оценки/кэша)

### Финальный шорт-лист на выбор парой

1. **Кейсы + инвентарь (#4)** — если важны вайб и ежедневный интерес  
2. **Мини-банк (A)** — если важнее всего строка в резюме и чистый backend  
3. **Билеты (B)** — компромисс: race + продукт + нормальное демо  
4. **Чат/доска (C/D)** или **квизы (#3)** — если оба больше про realtime и UI  

Правило: **один основной проект**, второй — только как фича/модуль, не параллельный репозиторий.

### Ещё 8 быстрых one-liner идей

1. **Парковка / бронирование мест** — слоты + датчики/статусы (логика как #2).  
2. **Обмен книгами в универе** — листинг, статусы сделки, чат по объявлению.  
3. **Трекер привычек с друзьями** — стрики, челленджи, лидерборд.  
4. **Свой markdown-блог с коллаб-правами** — версии, preview, роли.  
5. **Аукцион в реальном времени** — ставки, таймер, победитель (кусочек биржи).  
6. **Кинотеатр-очередь / watch party** — синхрон плеера + чат.  
7. **Склад / инвентарь для малого бизнеса** — остатки, списания, штрихкоды.  
8. **Платформа петиций / голосований** — антифрод голосов, кворум, дедлайны.

### Как не утонуть в выборе

Ответьте вдвоём на 3 вопроса:

1. Хотим больше **вайба** или больше **строки в резюме**?  
2. Больше **frontend/realtime** или **backend/данные**?  
3. Готовы ли к проекту на **2+ месяца** или нужен результат за **месяц**?

| Ответы | Берите |
|--------|--------|
| Вайб + realtime + быстро | #3 квизы / S Q&A / N ресторан |
| Вайб + хардкор экономика | #4 кейсы / T карточки / аукцион |
| Резюме + backend | #1 маркет / A банк / U flags / I splitwise |
| Резюме + «как работа» | #2 SaaS / L Jira / N ресторан + уведомления |
| AI, но не пустышка | AA RAG (+ лучше прикрутить к #3 через AC) |
